# 지도 POI 조회 전략 성능 비교

## 측정 목적

지도 Viewport를 타일로 분할해 병렬 조회하는 기존 방식과, 같은 범위를 하나의 확장 Viewport로 조회하는 방식을 비교했습니다. 서버 응답 성능이 개선된 현재 환경에서도 타일 분할 비용이 유효한지 검증하는 것이 목적입니다.

## 측정 조건

- iPhone 17 Pro Max Simulator, iOS 26.0
- Xcode Instruments 26.6
- 동일한 개발기 빌드와 서울 중심 좌표 및 줌 레벨
- 자동 초기 조회를 차단하고 `이 지역 재검색`을 한 번만 실행
- 두 전략 모두 최종 POI 125개 반환
- Time Profiler와 Allocations는 계측 오버헤드 분리를 위해 별도 Run으로 기록

## 판단

확장 Viewport 단일 요청은 기존 타일 합집합과 같은 영역을 조회하므로 화면 가장자리 바깥 POI를 미리 확보하는 동작을 유지합니다. 동일한 결과 수를 제공하면서 CPU, 메모리 할당, 네트워크 요청 및 안정 프레임 도달 시간이 모두 감소했으므로 단일 요청 전략을 채택합니다.

기존 타일 캐시는 제거하지 않고 동일한 TTL과 메모리 상한을 적용하는 지역 단위 캐시로 교체합니다. 이에 따라 같은 영역을 반복 조회할 때의 즉시 응답과 만료 데이터 fallback은 유지하면서, 타일 열거·병합·요청 공유를 위한 복잡도만 제거합니다.

## 측정 한계

시뮬레이터 측정값을 실기기의 절대 성능으로 일반화하지 않고 동일 환경에서의 상대 비교에만 사용합니다. Animation Hitches Instrument는 iOS Simulator에서 지원되지 않아 해당 수치를 추정하거나 다른 지표로 대체하지 않았습니다.
